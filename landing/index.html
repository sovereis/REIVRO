THE REWORK FIREWALL DIRECTION · PLANNED

VERIFY. LEARN.
PREVENT.

Your AI does the work. REIVRO verifies what actually happened.

Rework Firewall is designed to turn a caught mistake into a safeguard you can use on future work.

VERIFY · IN DEVELOPMENT

Don't trust completion claims without evidence.

Check the original task and acceptance criteria against the diff, repository search, tests and logs.

LEARN · PLANNED

Turn detected failures into reusable knowledge.

Capture reproducible mistakes and propose project-specific protections. Persistent rules require developer review and approval.

PREVENT · PLANNED

Don't fix the same mistake twice.

Apply reviewed safeguards to catch recurring issues before they create more rework. Support across coding agents remains unverified.

CONCEPTUAL EXAMPLE · NOT A PRODUCT EXECUTION

How Rework Firewall is designed to work

TASK
Replace all public references to an old production domain.
AGENT
“Done. All references updated.”
REIVRO
NOT VERIFIED
EVIDENCE (ILLUSTRATIVE)
A repository search finds 3 public references to the old domain.
SUGGESTED INVARIANT
Public domain migrations must leave zero legacy-domain references outside approved compatibility exceptions.

AVAILABLE · LOCAL MVP

What works today

Today's local MVP is the first step toward Rework Firewall. It analyzes public GitHub pull requests and grounds summary claims in traceable source excerpts. It checks cited excerpts against GitHub evidence, records execution results, and supports explicit human review and optional measurements.

Verification today covers the cited excerpts. Run the Workspace locally to try it.
