# SCOP implementation roadmap

This proposal prioritizes workflows with immediate customer value and repeatable evidence. Start with read-only sources and fixtures. Add account connectors, persistent state, and actions after their permission and failure behavior can be tested. Customer value estimates are assumptions for prioritization. The [catalog](CATALOG.md) lists suggested dependencies and integrations, and the [status guide](STATUS.md) defines advancement evidence.

| Order | Scope | Value, dependency, and complexity rationale |
| --- | --- | --- |
| 1. Validate the developer workflow | Route Pull Request Summary through maintainer review. Reproduce the Regression Test Generator and Test Failure Diagnosis prototypes, then exercise them on real repositories. Follow with Skills Inventory, Documentation Research, Verification Loop, and Code Reviewer. | Review and test triage are frequent tasks. GitHub read access, test output, and local fixtures support early checks with low integration overhead. |
| 2. Connect requirements to delivery | Start with UX Research Synthesizer, Product Requirements Generator, and Feature Specification Builder. Use their outputs for Code Architect, API Design, and QA Engineer. Add Debugging Specialist, Code Documentation, Library Migration, and Checklist Before Release. | Testable requirements provide reusable inputs for architecture, QA, and release checks. Text artifacts and repository fixtures keep the first delivery workflows easy to reproduce. |
| 3. Establish governance and web checks | Develop Project Permission MCP and Readable Audit Log first, then Module Governance, Phased Audit, Agent Audit Report, API Cost Review, and Security Review. In parallel, validate Browser Visual Check before browser-based accessibility, mobile, performance, and SEO audits. Use UX research to guide Design System Generator and Front-end Standards. | Shared permissions and audit evidence support higher-impact integrations. Browser fixtures give teams measurable web quality checks. Deployment Manager follows the release checklist and verified CI permissions and rollback behavior. |
| 4. Deliver read-only data and operations workflows | Start with Data Cleaning, SQL Query Builder, Google Sheets & Excel, Meeting Intelligence, and Business Process Mapper. Build dashboards and Data Storytelling from verified data, and derive SOPs and onboarding material from reviewed process maps. Add planning and scheduling drafts before calendar or project writes. | These workflows serve recurring reporting and coordination needs. Local files, schema snapshots, and meeting transcripts reduce initial connector complexity. |
| 5. Expand research, growth, and media | Validate Deep Research before the market and competitor workflows. Build competitive reports and strategy materials from reviewed evidence. Start media work with Article Writer, Front-end Slides, and Changelog Video. Build Video Editor and Animated CSV Charts before branding, programmatic rendering, and metrics videos. | Research and media share evidence patterns established earlier. Brand assets, rendering, CRM, and campaign tooling add integration and review effort, so stage them after standalone drafts. |
| 6. Pilot persistent, predictive, and sensitive workflows | Build Unified Memory before Cross-Session Memory and then test Knowledge Manager against authorized stores. Establish MLE Workflow and dataset evaluation before predictive workflows. Pilot contract, invoice, vendor, HR, and customer-account integrations with reviewed permissions. | These workflows require stronger evaluation and data controls. Test retention, access boundaries, and recovery for persistent context. Establish baselines and held-out evaluations before relying on forecasts or predictions. |

Within a phase, run independent work in parallel once its inputs are available. Prioritize repeat use, review effort saved, and reproducible failures when choosing the next skill. Revisit the order after the first pilots provide evidence about usage and integration cost.
